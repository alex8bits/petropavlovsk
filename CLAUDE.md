# Петропавловск

Браузерная 2D-оборона берега с физикой (HTML + JS, без сборки). Игрок командует береговой батареей
Петропавловского порта в 1854 году и отбивает англо-французскую эскадру. Готовы каркас (экраны, уровни как данные,
профиль, сохранения), кампания (11 боёв в 4 главах на 5 батареях, карта-схема губы, брифинги, итоги, звёзды),
мастерская (казна, 4 ветки прокачки, покупка бомб, тяжёлых и калёных ядер) и новый контент
(калёное ядро и пожар, пароход с колесом, флагман, французский флаг), полировка (звуки, подсказки обучения,
настройки, пороги звёзд).

Концепт будущей игры (цикл, кампания, прокачка, план работ): [docs/concept.md](docs/concept.md)
(копия документа https://claude.ai/artifact/Gn6qpWXeu93nLamh4tPAhv — там схемы и комментарии).
Все пять этапов плана выполнены (5 — «Полировка»: звуки, обучение, баланс звёзд). Дальше — первая версия
на руки игрокам и правки по их отзывам. Игра выложена: https://petropavlovsk.godnocode.ru (выкладка — скилл
`remote-server`). В работе — реалистичный звук, см. [«План: звук»](#план-звук-гибрид); следующее —
[«План: мобильное управление»](#план-мобильное-управление).

## Запуск

```bash
node server.js
```
Открыть http://localhost:8080. Сервер без зависимостей и отключает кэш: после правки — просто F5.
Физика planck.js@1.0.0 грузится с CDN (jsdelivr), шрифты (Old Standard TT — заголовки, PT Serif — текст и интерфейс боя) — с Google Fonts; нужен интернет, без него — запасной Georgia. Открывать `index.html` как файл нельзя:
скрипты не подтянутся.

## Код

Обычные `<script>` по порядку из `index.html`, общие глобальные объекты (не ES-модули):

| Файл | Что внутри |
|---|---|
| `js/config.js` | `BASE_CFG` — все числа и баланс (заморожен). `CFG` — рабочая копия текущего боя, пересобирается в `Game.start`. Менять баланс — в `BASE_CFG` |
| `js/audio.js` | `Settings` (звук, громкость, подсказки; свой ключ `localStorage`, «Новая кампания» не стирает), `Sound`: гибрид — записи (`recordings`, `recordingUse`, загрузка `loadRecordings`) и синтез Web Audio (`sfx`, он же запасной), эхо губы (`reverb`, `makeImpulse`, доли `wet`), прибой (`updateAmbient`) |
| `sounds/` | Записи MP3 (не обрезаны — кусок задаёт `Sound.recordings`), источники и лицензии — `CREDITS.md` |
| `js/tutorial.js` | `Tutorial`: подсказки по ходу боя из `level.tutorial` (шаги `when`/`done`/`after`, подсветка `focus`) |
| `js/physics.js` | `Physics`: мир planck, волны (`waterY`), плавучесть, сборка конструкций из кирпичей (ломкие weld-соединения), геометрия воды в трюме |
| `js/entities.js` | `Entities`: берег, крепость (размеры из `CFG.fortress`), пушка игрока, пушки крепости, корабли (корпус-«ванна», надстройка, пушки; имя, флаг, множители из записи эскадры), ядра; `Particles` |
| `js/main.js` | `Game`: бой — `start(level)`/`stop()`, шаг, попадания и урон, взрыв бомбы (`explode`), ИИ кораблей и пушек крепости, затопление, ремонт, порох, победа/поражение (потопить всех, продержаться, корабль ушёл), итоги и звёзды (`results()`). `MAX_POWDER` |
| `js/render.js` | `Render`: отрисовка на canvas (вид берега по `shore.kind`, туман) и интерфейс (кнопки панели кликабельны) |
| `js/flags.js` | Флаги (британский, Андреевский, французский) по эталонам Викимедиа, развеваются полосками |
| `js/profile.js` | `Profile`: профиль игрока (звёзды, казна, улучшения, ядра, место пушки поддержки) и сохранение в `localStorage` (`SAVE_KEY`, `SAVE_VERSION`, `MIGRATIONS`). Мастерская: `BRANCHES`, `UPGRADES` (цены, тексты, `apply(cfg, lvl)`), `UPGRADE_STARS`, `AMMO`; покупки, награда за бой (`rewardFor`), `Profile.maxed()` для бота |
| `js/levels.js` | `Batteries` — батареи (рельеф, кладка, пушки крепости, командир, точка на карте); `Levels`: реестр уровней, главы и пороги звёзд (`chapters`), формат уровня (комментарий в начале файла), `buildConfig(level, profile)` — база + батарея + уровень + профиль |
| `levels/*.js` | По файлу на бой: `Levels.add({...})`. Новый файл подключить в `index.html` |
| `js/screens.js` | `Screens`: HTML экранов (меню, карта кампании со схемой губы, мастерская, брифинг, пауза, итоги) |
| `js/app.js` | `App`: переключатель экранов, ввод, игровой цикл. Экраны — HTML в `#ui` поверх канваса, стили в `css/ui.css` |
| `tools/bot.js` | `Bot`: бот для баланса, в игру не подключён (загрузка — комментарий в файле). `Bot.run(id, {passive, ball, profile})`, `Bot.campaign({profile, runs})` |

Единицы — метры, секунды, кг; ось Y вверх. Фиксированный шаг 1/60 с.

## Ключевые решения (не переоткрывать без причины)

- **Порох:** 5 ступеней, 9,6/12,2/14,8/17,4/20 м/с (прежние 11…23, уменьшены × 20/23: максимум — как было на 4 мешках). Урон за джоуль поднят × 1,32 (23²/20²), чтобы урон выстрела остался прежним. Склад без прокачки 60 мешков,
  подвоз 1 мешок / 5,5 с; не хватает на заряд — выстрела нет (заряд не урезается). Пушки крепости порох не тратят.
  Уровень задаёт только стартовый запас — он может быть больше вместимости (подвоз идёт, лишь когда запас ниже неё).
- **Разброс** у всех выстрелов (`spread`, `speedSpread` у типов ядер); у пушки игрока — из прокачки
  (`playerCannon.spread`: ±2,5° и ±6% без прокачки, ±1° и ±2,5% на максимуме; другие ядра — в той же пропорции).
  Предпросмотр траектории — половина дуги.
- **Пушки ремонтируются, а не гибнут:** вражеские — перезарядка × 2 (11–12 с), с учётом команды; пушка игрока —
  12 с (8 с на максимуме прокачки).
  Проиграть можно только потерей крепости (< 50% кирпичей на месте).
- **Корабль тонет** от HP корпуса (урон = энергия удара) или от воды в трюме (≥ 55%). Корпус открыт сверху:
  ядра падают в трюм и остаются там, утяжеляя корабль. Вода заливается через ушедший под воду борт, переливается
  к нижнему борту, команда откачивает.
- **Мачта:** ядро задевает её с вероятностью 30%; ломается только от прямого попадания (ударная волна её не трогает);
  сломанная мачта — скорость × 0,5. **Пароход** (`steamer`, бой 2 и Virago в боях 3–5, 7, 10, 11): мачта и гребное
  колесо (`wheelHp`, урон как по пушке, не чинится, открыта только часть над бортом); каждый потерянный движитель —
  минус треть скорости (`propulsionLoss`). Труба и дым — только рисунок. **Команда** = доля уцелевших досок рубки; от неё — скорость откачки и ремонта.
- **Калёное ядро и пожар** (`balls.hot`, `CFG.fire`): ядро поджигает корабль при первом касании, пока не остыло
  (`ball.heat`, 15 с; в воде — сразу 0), в трюме — подпитывает огонь. Очаги (`ship.fires`, до 3) растут сами,
  команда тушит (`extinguish × crew`); огонь ест корпус и доски в радиусе 0,8 м. Очаг на борту полная команда
  гасит; очаг у рубки сжигает её — корабль сгорает. В источниках о Петропавловске калёные ядра не упоминаются —
  в текстах игры не утверждать, что их там применяли.
- **Бомба** (`balls.bomb`, `CFG.blast`): полое ядро с порохом (легче чугунного, крупнее). Первый удар обо что угодно,
  кроме воды, поджигает трубку — взрыв через 0,5 с там, где бомба окажется (`ball.fuseTimer`); в воде трубка гаснет
  (`ball.fuse = false`), бомба тонет. При взрыве — 10 осколков (`Game.shards`): по 5 вправо и влево, под 0°, ±20° и ±60°
  к горизонту, квадрат массой 0,1 бомбы, 30 м/с; осколок — ядро типа `shard` (бьёт как обычное, в точность
  игрока не идёт, осколки друг с другом не сталкиваются). Взрыв — урон с долей
  `1 − d/R` (R = 1,8 м) корпусу (расстояние до корпуса или надстройки), пушкам и колесу, доскам и кирпичам (рвёт
  соединения, расталкивает); мачту не ломает. Свою крепость тоже рвёт, если бомба упала на неё. Покупается с главы 2.
  С бомбами прочность кораблей поднята примерно в 1,7 раза (+15%, затем × 1,5): шлюп 450, фрегат 720, пароход 500, флагман 960
  (раньше корабль тонул от 2–3 точных попаданий чугуном — игроку слишком легко). Бой без прокачки
  стал заметно труднее, это принято (решение пользователя).
- **Флагман** (`flagship`, President в бою 11): 3 пушки, 960 HP, рубка 4 × 3. В бою 11 огонь эскадры реже
  на 20% — без этого бот без прокачки проигрывал на низкой кладке батареи № 3.
- **Пушки крепости** (башня и стена): автоматические, лёгкое ядро, ошибка наводки ±6°, дальность 32 м;
  гибнут от вражеского ядра или упав вместе с кладкой. Были слишком сильными — ослаблены намеренно.
  `fortGuns.count` у батареи — число мест; стоит пушек `min(места, прокачка)`, без прокачки — ни одной.
  Одну пушку на двух местах игрок ставит на стену или башню (брифинг, `Profile.data.fortSpot`).
- **Мастерская:** одна валюта — казна. Корабль даёт награду при каждом потоплении (и в проигранном бою),
  звезда — один раз, когда получена впервые (`economy`). Прокачка — абсолютные значения по уровню
  (`UPGRADES[k].apply` вызывается и для уровня 0); старшие уровни открываются звёздами (`UPGRADE_STARS`).
  Ядра покупаются пачками по 3: бомбы — с главы 2, тяжёлые — с главы 3, калёные — с главы 4; купленное остаётся навсегда — каждый бой
  с полным запасом, уровень может выдать ядра сверх купленных (`config.ammo`: тяжёлые в боях 5 и 7, калёные —
  в 8 и 11). Чугунное — без счёта.
- **Земляной вал** (3 уровня): статичный откос между стеной и пушкой игрока, принимает ядра и не рушится,
  в целостность крепости не входит. Прочность кладки умножает `jointBreakForce`/`jointBreakTorque`.
- **История:** игра про 1854 год. Британские корабли — Юнион Джек образца 1801 г., французские — триколор;
  над крепостью — Андреевский флаг (белый с синим косым крестом). Батареи, командиры,
  кто какую батарею атаковал — по статье «Петропавловская оборона». Пароход 17 августа в источнике не назван —
  в игре он «Пароход», не Virago. Новые исторические детали сначала сверять с источниками.
- **Кампания:** бой n+1 открывается победой в бою n; первому бою главы нужно ещё набрать звёзды
  (`Levels.chapters`: 0/2/4/10). Победа даёт минимум звезду, так что кампания всегда проходима переигровками.
- **Корабли не сталкиваются друг с другом** (`onPreSolve`): в глубине сцены они на разных линиях, дальний проходит
  мимо ближнего. Учебные щиты всё равно спавнить с интервалом — так задумано в бою 1.
- **Звук:** события боя — через `Sound.event`, он молчит при `Game.paused`, поэтому бот и прогоны `Game.step`
  беззвучны. Тихие удары (< 15% от полного заряда) не звучат, у частых звуков есть мин. интервал (`Sound.gap`).
  AudioContext запускается по первому жесту игрока. M — звук вкл/выкл.
  **Принят гибрид** (вместо прежнего «только синтез, без файлов»): записи — только для выстрелов, удара
  по дереву, всплеска и треска мачты/колеса, всё остальное — синтез; эхо — общее для всех звуков боя. Слушатель — зритель перед серединой поля:
  панорама по `x`, без задержки по расстоянию.
  Без записи (не загрузилась, нет файла) событие звучит синтезом — игра никогда не молчит из-за файла.
- **Обучение:** подсказки не останавливают бой, идут по одной, показываются, пока бой не выигран (и включены
  в настройках). Полное — бои 1–2, по 1–2 подсказки — в боях с новой механикой (3, 4, 5, 8, 9).
- **Звёзды:** порог пороха для 3-й звезды ≈ медиана бота без прокачки × 1,15 (бот целится идеально — человеку
  без прокачки трудно, с точностью — достижимо); звезда — 90 руб. (казна одного прохода ≈ 2/3 прокачки).
- **Условия боя:** `sinkAll`; `survive` — продержаться `time` с, потом уцелевшие уходят; `leaveAt` у корабля —
  ушёл живым, бой проигран (пароход в бою 2). Учебный бой без ответного огня поражением не кончается.

## План: звук (гибрид)

Цель — звук открытого берега 1854 года вместо «условного»: сейчас каждый звук в `js/audio.js` — фильтрованный
шум и тон со спадом, сухой, без эха, расстояния и вариаций. Этапы по порядку; каждый слушает пользователь
(агент звук не слышит — проверяет только, что события срабатывают и ошибок нет), следующий — после его «да».

1. **Эхо и место на экране** (синтез, без файлов). Слушатель — зритель перед серединой поля (вид сбоку,
   камера неподвижна), а не пушка игрока: задержки по расстоянию нет (отставание звука от вспышки читалось бы
   как лаг). Общая цепочка после `play`: прямой звук + `ConvolverNode` с откликом, синтезированным при `unlock`
   (затухающий шум ~3 с и отдельные поздние эхо 0,3–1 с — склоны губы); доля эха — своя у каждого звука,
   у звуков интерфейса — ноль. Панорама по `x` — как была; к краям поля звук слегка глуше (`lowpass`)
   и с чуть большей долей эха. Линий глубины в данных нет — по ним звук не меняется.
   Готово, когда: залп своей пушки раскатывается эхом по губе, звуки у краёв поля чуть глуше, чем в середине.
2. **Записи и загрузчик.** Папка `sounds/` (MP3 — играет во всех браузерах), 2–4 варианта на событие,
   на воспроизведении — случайный сдвиг высоты (`playbackRate` ±5–8%) и громкости. Записи: выстрел (свой,
   корабля, пушки поддержки — один набор с разной обработкой), удар ядра о дерево, всплеск, треск мачты/колеса.
   Загрузка — в фоне при `unlock` (`fetch` + `decodeAudioData`), не задерживает меню; без записи — синтез (`sfx`).
   В `server.js` — тип `.mp3` (`audio/mpeg`). Бюджет — до ~3 МБ на все записи.
   Лицензии: только CC0 или CC BY; источник, автор и лицензия каждого файла — в `sounds/CREDITS.md`
   (CC BY — с упоминанием автора и в игре, в справке настроек). Файлы подбирает и слушает пользователь;
   агент может искать кандидатов (Freesound и т. п.), но не скачивает без подтверждения.
   Готово, когда: четыре события звучат записями с вариациями, а при удалённой папке `sounds/` — синтезом.
   *Сделано, ждёт прослушивания:* 6 записей (~800 КБ, превью Freesound), ffmpeg нет — файлы не режутся,
   кусок `[файл, начало, длина, громкость]` вырезается при проигрывании. Выстрел — 4 варианта из 3 записей
   (глухой CivilWarCannonFire убран: мало высоких, на фоне других казался пропавшим; новые сверены
   по доле высоких и громкости первых 0,3–1 с), треск — 2,
   удар о дерево и всплеск — по одной записи (разнообразие — разбросом высоты и громкости).
   Этап 1 (эхо) тоже ждёт прослушивания.
3. **Выстрел слоями.** Поверх записи (и в синтезе для запасного варианта): резкий щелчок (короткая перегрузка
   `WaveShaperNode`), удар и раскатистый хвост через эхо этапа 1; сила — от заряда, как сейчас (`power`).
4. **Синтез, который остаётся.** Металл и камень — несколько резонансных фильтров с разными частотами
   и затуханием вместо «окрашенного шума»; всплеск синтеза и затопление — пузырьки (короткие тона с ростом
   частоты); пожар — треск по росту очага.
5. **Фон.** Ветер (сильнее в волнение, бой 9), скрип рангоута у ближних кораблей, чайки в тишине между
   залпами — синтезом или 1–2 короткими записями в петле, тише прибоя.

Правила на все этапы: события — по-прежнему только через `Sound.event` (бот и `Game.step` беззвучны),
`Sound.gap` и порог тихих ударов сохраняются, громкость — общий `master` и настройки. Новых зависимостей
нет. Выкладка: `sounds/` добавить в список файлов скилла `remote-server` (раздел «What gets deployed»
и команда `git archive`) вместе с этапом 2. По завершении — обновить строку `js/audio.js` в таблице «Код»
и решение «Звук».

## План: мобильное управление

Цель — бой играбелен с телефона боком (landscape), клавиатура и мышь на компьютере работают как прежде.
Сейчас на телефоне работают HTML-экраны и кнопки канваса (порох, ядро, «Огонь!» — `click`), но угол меняют
только ↑↓ и колесо (`js/app.js`), пауза — только Esc, а панель боя масштабируется от поля (`u = s / 30`
в `Render.drawHUD`): на экране 844 × 390 текст ~6 px, кнопка пороха ~17 px. Логика боя (`Game`) не меняется —
касания вызывают то же, что клавиши: `cannon.angle`, `cannon.powder`, `playerFire`, `cycleBall`, `App.pause`.
Этапы по порядку; каждый проверяет пользователь на своём телефоне (эмуляция в панели браузера шлёт касания
как мышь — проверяет только раскладку и что ничего не сломалось на компьютере).

1. **Наводка касанием.** Pointer Events на канвасе, `touch-action: none` (страница не прокручивается
   и не масштабируется). Протяжка пальцем вверх-вниз по полю (вне панелей) меняет угол относительно
   (≈ 1° на 8–10 px, подобрать), пока палец на экране — траектория видна как сейчас; отпускание не стреляет.
   Плюс кнопки ▲ ▼: пока кнопка зажата, держат `Game.keys.ArrowUp`/`ArrowDown` — угол плавно меняет
   `Game.step` (`turnSpeed`), как от клавиш; свой автоповтор не нужен. Выстрел — только кнопкой «Огонь!».
   Готово, когда: на телефоне можно навести и выстрелить, на компьютере ↑↓, колесо и пробел — как были.
   *Сделано, ждёт проверки на телефоне:* `Render.onPointer*` — протяжка начинается где угодно, кроме кнопок
   (на панели тоже), мышью протяжка не наводит; 8 px на градус (`Render.AIM_PX_PER_DEG`). Управление пальцем —
   внизу экрана (решение пользователя): ▲ ▼ столбиком в левом нижнем углу, «Огонь!» — в правом нижнем
   (≥ 40 CSS px), только на сенсорном экране (`Render.touch`: `any-pointer: coarse` или было касание).
2. **Панель боя для пальца.** Панель боя — HTML поверх канваса (стили в `css/ui.css`), а не рисунок канваса.
   Контейнер — свой (`#hud` рядом с `#ui`), не `#ui`: в бою `App.show('battle')` очищает и прячет `#ui`,
   а пауза и итоги (поверх идущего боя) перезаписывают его `innerHTML`; панель видна только на экране боя. Раскладку под телефон и компьютер задаёт CSS, кнопки — не меньше 44 px
   при любом масштабе поля. На телефоне — компактно: внизу полоса «▲ ▼ · порох 1–5 · ядро · Огонь!»,
   сверху справа — склад, пушка, крепость, таймер ухода, одной строкой. Обновлять DOM только при изменении
   значений (не каждый кадр). Подсветка подсказок (`Tutorial`, `focus`: `angle`, `powder`, `fire`…) берёт
   прямоугольники элементов панели вместо `Render.hud` (`getBoundingClientRect` → пиксели канваса).
   Плашку подсказки (`Render.drawHint`, сейчас — между панелями по числам `324 * u` и `W - 274 * u`)
   ставить по фактическим краям панелей: на телефоне — над нижней полосой. На компьютере вид — как сейчас.
   Готово, когда: на 844 × 390 всё читается и нажимается пальцем, подсказки подсвечивают нужное.
3. **Пауза, ориентация, экран.** Кнопка паузы на панели. В портрете на сенсорном экране — заставка
   «Поверните телефон» (CSS `orientation: portrait` + `pointer: coarse`), бой ставится на паузу.
   Кнопка «На весь экран» (Fullscreen API; на iPhone Safari его нет — тогда кнопку не показывать)
   и, где можно, `screen.orientation.lock('landscape')`. Размер — по `visualViewport` (адресная строка
   меняет высоту) с учётом выреза (`env(safe-area-inset-*)`). `devicePixelRatio` ограничить 2 —
   иначе канвас на телефоне ~2500 px в ширину и тормозит.
4. **Тексты под касания.** Тип ввода — по последнему `pointerType` (касание/мышь) и клавишам; от него —
   подсказки обучения (боям 1–2: `text` уже может быть функцией), справка «Управление» в настройках
   и подписи панели («↑↓ / колесо» → «проведите пальцем»). Двойное касание не масштабирует
   (`touch-action: manipulation` на экранах), долгое нажатие не вызывает меню (`-webkit-touch-callout: none`).
   Звук на iPhone молчит при беззвучном режиме — упомянуть в справке.

Правила на все этапы: клавиатура и мышь не ломаются; бот и `Game.step` не трогаются (ввод — только
в `App`/`Render`/панели); баланс не меняется — сложность наводки пальцем, если окажется выше, решать
отдельно, по отзывам. По завершении — обновить таблицу «Код» и добавить решение «Мобильное управление».

## Проверка

Тестов нет; проверяю в браузере (`.claude/launch.json` → сервер `game`) через JS в консоли страницы:
`App.act('start', {id: 'training'})` (или `Game.start(Levels.get('training'))`), `Game.paused = true`,
чтобы кадры не шагали сами, затем `Game.step(1/60)` в цикле — это прогоняет бой мгновенно.
Конец боя — `Game.endReported` (через 2,5 с после победы/поражения), итоги — `Game.results()`. Приёмы:
- отключить спавн уровня: `CFG.fleet.forEach(e => e.t += 1e6)` (действует до следующего `Game.start`);
- создать корабль вручную: `Game.ships.push(Entities.createShip('frigate', 30, 30))`;
- бот для баланса: `tools/bot.js` → `Bot.run('krasny-yar', {ball: 'heavy'})` (или список по предпочтению,
  `ball: ['bomb', 'hot', 'heavy']` — так стреляет `Bot.campaign`) — исход, потоплено, крепость, порох,
  звёзды (без записи в сохранение). Внутри: `Game.solveFromMuzzle` с упреждением и наименьший достаточный заряд.
  `profile: 'zero'` (по умолчанию) — без улучшений, `'max'` — всё прокачано, `'save'` — текущее сохранение.
  Кампания целиком без зависания вкладки: `Bot.campaign({profile: 'zero', runs: 3})`, сводка — `Bot.report`
  (готово, когда `Bot.done`). Ориентир: без прокачки бот выигрывает каждый бой хотя бы в половине попыток,
  с полной — все и на три звезды;
- на лету менять батарею или уровень: `Batteries.koshka.config.fortress.wallRows = 9`, `Levels.get(id).fleet` —
  `buildConfig` читает их при каждом старте (до перезагрузки страницы);
- «пассивный» прогон (игрок не стреляет) должен заканчиваться поражением, бот — побеждать;
- бой через `App` пишет результат в сохранение: для чистого профиля — `Profile.reset()`.
Долгий цикл одним вызовом JS может упереться в таймаут инструмента: 2–3 боя на вызов. Если панель браузера
скрыта, кадры не рисуются: перед скриншотом — `Render.draw(Game)`, а текст экранов — через `get_page_text`.

После изменений баланса прогонять оба варианта по 3–4 раза: исход случайный (разброс, волны).

## Работа агентов

- Сессия, получившая запрос пользователя, — **оркестратор**: держит контекст, планирует, принимает решения
  и проверяет результат. Части работы при необходимости отдаёт субагентам.
- Главный критерий — **экономия бюджета при сохранении качества**: каждой задаче — самая дешёвая модель,
  которая справится с ней хорошо. Модель задаётся явно (`model` при запуске субагента).
  - **Haiku** — поиск по коду, чтение и пересказ файлов, механические правки по точному описанию,
    прогоны бота и сбор цифр (`Game.step` в цикле, сводка исходов).
  - **Sonnet** — реализация чётко описанной фичи или экрана, рефакторинг, проверка в браузере,
    правки документации по готовому решению.
  - **Opus** — архитектура (каркас, формат уровней, профиль), физика и баланс, неоднозначные задачи
    без готового решения, ревью сложных изменений.
- Субагент не нужен, если задача решается парой вызовов инструментов: запуск с нуля стоит дороже.
  Самостоятельные части без общих файлов можно отдавать параллельно.
- Бриф субагенту — полный и короткий: какие файлы, что сделать, что считать готовым, какие решения
  из этого файла соблюдать. Результат субагента оркестратор проверяет сам, прежде чем сообщать пользователю.
