# Петропавловск

Браузерная 2D-оборона берега с физикой (HTML + JS, без сборки). Игрок командует береговой батареей
Петропавловского порта в 1854 году и отбивает англо-французскую эскадру. Готовы каркас (экраны, уровни как данные,
профиль, сохранения), кампания (11 боёв в 4 главах на 5 батареях, карта-схема губы, брифинги, итоги, звёзды)
и мастерская (казна, 4 ветки прокачки, покупка тяжёлых ядер).

Концепт будущей игры (цикл, кампания, прокачка, план работ): [docs/concept.md](docs/concept.md)
(копия документа https://claude.ai/artifact/Gn6qpWXeu93nLamh4tPAhv — там схемы и комментарии).
Этапы 1 «Каркас», 2 «Кампания» и 3 «Мастерская» выполнены. Ближайший этап по плану: **новый контент**
(калёное ядро и пожар, парусно-паровой шлюп с колесом, флагман).

## Запуск

```bash
node server.js
```
Открыть http://localhost:8080. Сервер без зависимостей и отключает кэш: после правки — просто F5.
Физика planck.js@1.0.0 грузится с CDN (jsdelivr) — нужен интернет. Открывать `index.html` как файл нельзя:
скрипты не подтянутся.

## Код

Обычные `<script>` по порядку из `index.html`, общие глобальные объекты (не ES-модули):

| Файл | Что внутри |
|---|---|
| `js/config.js` | `BASE_CFG` — все числа и баланс (заморожен). `CFG` — рабочая копия текущего боя, пересобирается в `Game.start`. Менять баланс — в `BASE_CFG` |
| `js/physics.js` | `Physics`: мир planck, волны (`waterY`), плавучесть, сборка конструкций из кирпичей (ломкие weld-соединения), геометрия воды в трюме |
| `js/entities.js` | `Entities`: берег, крепость (размеры из `CFG.fortress`), пушка игрока, пушки крепости, корабли (корпус-«ванна», надстройка, пушки; имя, флаг, множители из записи эскадры), ядра; `Particles` |
| `js/main.js` | `Game`: бой — `start(level)`/`stop()`, шаг, попадания и урон, ИИ кораблей и пушек крепости, затопление, ремонт, порох, победа/поражение (потопить всех, продержаться, корабль ушёл), итоги и звёзды (`results()`). `MAX_POWDER` |
| `js/render.js` | `Render`: отрисовка на canvas (вид берега по `shore.kind`, туман) и интерфейс (кнопки панели кликабельны) |
| `js/flags.js` | Флаги (британский, российский, французский) по эталонам Викимедиа, развеваются полосками |
| `js/profile.js` | `Profile`: профиль игрока (звёзды, казна, улучшения, ядра, место пушки поддержки) и сохранение в `localStorage` (`SAVE_KEY`, `SAVE_VERSION`, `MIGRATIONS`). Мастерская: `BRANCHES`, `UPGRADES` (цены, тексты, `apply(cfg, lvl)`), `UPGRADE_STARS`, `AMMO`; покупки, награда за бой (`rewardFor`), `Profile.maxed()` для бота |
| `js/levels.js` | `Batteries` — батареи (рельеф, кладка, пушки крепости, командир, точка на карте); `Levels`: реестр уровней, главы и пороги звёзд (`chapters`), формат уровня (комментарий в начале файла), `buildConfig(level, profile)` — база + батарея + уровень + профиль |
| `levels/*.js` | По файлу на бой: `Levels.add({...})`. Новый файл подключить в `index.html` |
| `js/screens.js` | `Screens`: HTML экранов (меню, карта кампании со схемой губы, мастерская, брифинг, пауза, итоги) |
| `js/app.js` | `App`: переключатель экранов, ввод, игровой цикл. Экраны — HTML в `#ui` поверх канваса, стили в `css/ui.css` |
| `tools/bot.js` | `Bot`: бот для баланса, в игру не подключён (загрузка — комментарий в файле). `Bot.run(id, {passive, ball, profile})`, `Bot.campaign({profile, runs})` |

Единицы — метры, секунды, кг; ось Y вверх. Фиксированный шаг 1/60 с.

## Ключевые решения (не переоткрывать без причины)

- **Порох:** 5 ступеней, 11/14/17/20/23 м/с (максимум 23 — как было при 4 ступенях). Склад без прокачки 60 мешков,
  подвоз 1 мешок / 5,5 с; не хватает на заряд — выстрела нет (заряд не урезается). Пушки крепости порох не тратят.
  Уровень задаёт только стартовый запас — он может быть больше вместимости (подвоз идёт, лишь когда запас ниже неё).
- **Разброс** у всех выстрелов (`spread`, `speedSpread` у типов ядер); у пушки игрока — из прокачки
  (`playerCannon.spread`: ±2,5° и ±6% без прокачки, ±1° и ±2,5% на максимуме; другие ядра — в той же пропорции).
  Предпросмотр траектории — половина дуги.
- **Пушки ремонтируются, а не гибнут:** вражеские — перезарядка × 2 (11–12 с), с учётом команды; пушка игрока —
  12 с (8 с на максимуме прокачки).
  Проиграть можно только потерей крепости (< 50% кирпичей на месте).
- **Корабль тонет** от HP корпуса (урон = энергия удара) или от воды в трюме (≥ 55%). Корпус открыт сверху:
  ядра падают в трюм и остаются там, утяжеляя корабль. Вода заливается через ушедший под воду борт, переливается
  к нижнему борту, команда откачивает.
- **Мачта:** ядро задевает её с вероятностью 30%; ломается только от прямого попадания (ударная волна её не трогает);
  сломанная мачта — скорость × 0,5. **Команда** = доля уцелевших досок рубки; от неё — скорость откачки и ремонта.
- **Пушки крепости** (башня и стена): автоматические, лёгкое ядро, ошибка наводки ±6°, дальность 32 м;
  гибнут от вражеского ядра или упав вместе с кладкой. Были слишком сильными — ослаблены намеренно.
  `fortGuns.count` у батареи — число мест; стоит пушек `min(места, прокачка)`, без прокачки — ни одной.
  Одну пушку на двух местах игрок ставит на стену или башню (брифинг, `Profile.data.fortSpot`).
- **Мастерская:** одна валюта — казна. Корабль даёт награду при каждом потоплении (и в проигранном бою),
  звезда — один раз, когда получена впервые (`economy`). Прокачка — абсолютные значения по уровню
  (`UPGRADES[k].apply` вызывается и для уровня 0); старшие уровни открываются звёздами (`UPGRADE_STARS`).
  Тяжёлые ядра покупаются пачками по 3 с главы 3; купленное остаётся навсегда — каждый бой с полным запасом,
  уровень может выдать ядра сверх купленных (`config.ammo`, бои 5 и 7). Чугунное — без счёта.
- **Земляной вал** (3 уровня): статичный откос между стеной и пушкой игрока, принимает ядра и не рушится,
  в целостность крепости не входит. Прочность кладки умножает `jointBreakForce`/`jointBreakTorque`.
- **История:** игра про 1854 год. Британские корабли — Юнион Джек образца 1801 г., французские — триколор;
  над крепостью — бело-сине-красный флаг (чёрно-жёлто-белый — анахронизм, он с 1858 г.). Батареи, командиры,
  кто какую батарею атаковал — по статье «Петропавловская оборона». Пароход 17 августа в источнике не назван —
  в игре он «Пароход», не Virago. Новые исторические детали сначала сверять с источниками.
- **Кампания:** бой n+1 открывается победой в бою n; первому бою главы нужно ещё набрать звёзды
  (`Levels.chapters`: 0/2/4/10). Победа даёт минимум звезду, так что кампания всегда проходима переигровками.
- **Корабли не сталкиваются друг с другом** (`onPreSolve`): в глубине сцены они на разных линиях, дальний проходит
  мимо ближнего. Учебные щиты всё равно спавнить с интервалом — так задумано в бою 1.
- **Условия боя:** `sinkAll`; `survive` — продержаться `time` с, потом уцелевшие уходят; `leaveAt` у корабля —
  ушёл живым, бой проигран (пароход в бою 2). Учебный бой без ответного огня поражением не кончается.

## Проверка

Тестов нет; проверяю в браузере (`.claude/launch.json` → сервер `game`) через JS в консоли страницы:
`App.act('start', {id: 'training'})` (или `Game.start(Levels.get('training'))`), `Game.paused = true`,
чтобы кадры не шагали сами, затем `Game.step(1/60)` в цикле — это прогоняет бой мгновенно.
Конец боя — `Game.endReported` (через 2,5 с после победы/поражения), итоги — `Game.results()`. Приёмы:
- отключить спавн уровня: `CFG.fleet.forEach(e => e.t += 1e6)` (действует до следующего `Game.start`);
- создать корабль вручную: `Game.ships.push(Entities.createShip('frigate', 30, 30))`;
- бот для баланса: `tools/bot.js` → `Bot.run('krasny-yar', {ball: 'heavy'})` — исход, потоплено, крепость, порох,
  звёзды (без записи в сохранение). Внутри: `Game.solveFromMuzzle` с упреждением и наименьший достаточный заряд.
  `profile: 'zero'` (по умолчанию) — без улучшений, `'max'` — всё прокачано, `'save'` — текущее сохранение.
  Кампания целиком без зависания вкладки: `Bot.campaign({profile: 'zero', runs: 3})`, сводка — `Bot.report`
  (готово, когда `Bot.done`). Ориентир: без прокачки бот выигрывает каждый бой хотя бы в половине попыток,
  с полной — все и на три звезды;
- на лету менять батарею или уровень: `Batteries.koshka.config.fortress.wallRows = 9`, `Levels.get(id).fleet` —
  `buildConfig` читает их при каждом старте (до перезагрузки страницы);
- «пассивный» прогон (игрок не стреляет) должен заканчиваться поражением, бот — побеждать;
- бой через `App` пишет результат в сохранение: для чистого профиля — `Profile.reset()`.
Долгий цикл одним вызовом JS может упереться в таймаут инструмента: 2–3 боя на вызов. Если панель браузера
скрыта, кадры не рисуются: перед скриншотом — `Render.draw(Game)`, а текст экранов — через `get_page_text`.

После изменений баланса прогонять оба варианта по 3–4 раза: исход случайный (разброс, волны).

## Работа агентов

- Сессия, получившая запрос пользователя, — **оркестратор**: держит контекст, планирует, принимает решения
  и проверяет результат. Части работы при необходимости отдаёт субагентам.
- Главный критерий — **экономия бюджета при сохранении качества**: каждой задаче — самая дешёвая модель,
  которая справится с ней хорошо. Модель задаётся явно (`model` при запуске субагента).
  - **Haiku** — поиск по коду, чтение и пересказ файлов, механические правки по точному описанию,
    прогоны бота и сбор цифр (`Game.step` в цикле, сводка исходов).
  - **Sonnet** — реализация чётко описанной фичи или экрана, рефакторинг, проверка в браузере,
    правки документации по готовому решению.
  - **Opus** — архитектура (каркас, формат уровней, профиль), физика и баланс, неоднозначные задачи
    без готового решения, ревью сложных изменений.
- Субагент не нужен, если задача решается парой вызовов инструментов: запуск с нуля стоит дороже.
  Самостоятельные части без общих файлов можно отдавать параллельно.
- Бриф субагенту — полный и короткий: какие файлы, что сделать, что считать готовым, какие решения
  из этого файла соблюдать. Результат субагента оркестратор проверяет сам, прежде чем сообщать пользователю.
